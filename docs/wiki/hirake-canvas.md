フォルダ配下の全文書をズーム可能な無限キャンバスへ空間配置するモード（**Ctrl+Shift+C**）。

## ズーム段階で表示が変わる

| ズーム | 表示 |
|---|---|
| 遠い | リンクグラフ |
| 中間 | サムネイル付きカード |
| 近い | 中央付近の文書が**実物のインラインプレビュー**になる |

インラインプレビューは**同時に最大 3 枚**で、遠ざかると自動で破棄される。

### カードの重なり順

プレビュー（420×320）はリンク距離（120）より大きいので、**隣り合うノードのカードは必ず重なる**。配置を広げて重なりを無くす道は採っていない。ピン留め済みノードは動かせず（[[#配置の記憶]]）、レイアウトを数倍に広げると全体俯瞰が収まらなくなるため。代わりに「**どれを手前に出すか**」を決めている。

| 状態 | 前後 |
|---|---|
| 通常カード | 最背面 |
| プレビュー | 通常カードより前。**ビューポート中心に近いものほど手前** |
| ポインタが乗っている | さらに前 |
| クリックで固定 | 最前面（ポインタを外しても残る） |

- **完全に隠れたカードは、その方向へパンすれば手前に出る。** 中心距離で順位が決まるため。ドラッグでずらす必要が無い＝読むためだけの操作がピン留めとして永続化されない
- 重なり順は**インラインの `z-index` だけで決める**。CSS 側には置かない（インライン指定はセレクタに勝つので、両方に書くと `:hover` の指定が効かなくなる）
- 値はカード層（`#cv-cards`）の内側でしか効かない。この層は `transform` を持ち独立した stacking context を作るため、**左上の情報バーは常にカードより前**

## プレビューの制約

プレビューは**静的表示**で、スクリプトを実行しない。そのため **Mermaid・数式・シンタックスハイライトは出ない**。完全な表示を見るにはタイトル部分をダブルクリックして通常タブへ移る。

## ナレッジグラフとの関係

ナレッジグラフ（Ctrl+G）は独立したビューではなく、**このキャンバスの「全体俯瞰」として開く**入口。そのままズームインして中身まで見に行ける。対して Ctrl+Shift+C は**前回の視点で再開**する。

### 俯瞰の収め方

全体俯瞰は「**全ノードが画面に収まっている**」ことを期待動作とする。そのため収める範囲は**ノード中心ではなく描画範囲**で求める。

- **円の半径とラベルの実測幅を含めた占有矩形**を集約する。ラベルは円の下（`半径 + 14`）へ中央揃えで出るため、上下で式が非対称になる
- ラベル幅は**オフスクリーン canvas の `measureText`** で測る。カードモードでは `.cv-node-label` が `display: none` になるため `getBBox()` は使えない。計測用のフォントは `getComputedStyle` から引く（ハードコードするとテーマやフォント設定の変更で静かにずれる）
- **余白は画面 px（24px）で持つ。** ワールド単位の余白はズーム率に比例して痩せるので、大きなフォルダほど実質の余白が無くなる
- 左上の情報バーと左下のヒントは常時表示のため、**その分を差し引いた矩形**の中央へ合わせる

ズーム下限（`0.1`）に当たった場合はこの計算でも全体が収まらない。そのときはコンソールへ 1 行だけ記録する（下限そのものを動かすかは別の判断）。

## 配置の記憶

ドラッグ配置は**ピン留め**として記憶される。

ピン留め（`canvas-layout`）は**ワークスペースには保存されず、アプリ全体で共有される**。同じフォルダを含む 2 つのワークスペースが別々の座標を持つと、手動配置のどちらが正しいか決められなくなるため。ワークスペースが保存するのは**視点（パン位置とズーム率）だけ**。→ [[hirake-workspaces]]
