Obsidian などで使われる `[[ページ名]]` を、Hirake がふつうのリンクとして扱う仕組み。**探索機能（ナレッジグラフ・バックリンク・キャンバス）に同じリンクが乗ることが目的**であって、記法の見た目を整えることが目的ではない。

## なぜ必要だったか

Hirake は「フォルダに溜まった Markdown を知識ベースとして横断的に探索できる」ことを差別化点に置いている（[[hirake-overview]]）。ところが Wiki 形式の文書群では、リンクの大半が `[[...]]` で書かれる。対応していない状態では**その文書群のリンク構造がゼロに見える**ため、[[hirake-knowledge-exploration]] の機能が丸ごと空振りしていた。

## 設計の芯

**`[[...]]` を Markdig の AST に `LinkInline` として載せる。** 独自の要素を作らず、レンダリング後の HTML も後処理しない。

こうすると、`LinkInline` を前提に既に書かれている経路がすべて追随する。

| 追随するもの | 追加実装 |
|---|---|
| HTML への描画（`HtmlRenderer`） | 不要 |
| `.md` リンクを新タブで開く制御（`DocumentTab.DecideNavigation`） | 不要 |
| 依存グラフ（`LinkGraphService.ExtractMarkdownLinkTargets`） | 不要 |
| バックリンクパネル・キャンバス・ナレッジグラフ | 不要（同じグラフを使う） |

独自の型を足したり HTML を後処理したりすると、この波及が効かなくなる。

## 対応する記法

| 記法 | 意味 |
|---|---|
| `[[target]]` | target を開く |
| `[[target\|表示名]]` | 表示名を変えて target を開く |
| `[[target#見出し]]` | target の該当見出しへスクロールする |
| `[[folder/target]]` | フォルダを指定して曖昧さをなくす |

`![[...]]`（埋め込み）と `[[#見出し]]`（自ファイル内アンカー）は対象外。

## 名前解決

名前 → ファイルパスの索引（`WikiLinkIndex`）で引く。

- **索引は本文を読まない。** ファイルパスの列挙だけで作る。500 ファイルの実測で、パス列挙のみなら 1〜6 ms、実際に使う経路（リンク実体の解決を含む）でも 34〜47 ms。本文まで読む作りにすると初回は 4.6 秒かかることを実測で確認しており、描画のたびに払える額ではない
- 列挙は横断検索・グラフと同じ `FolderSearchService.EnumerateMarkdownFiles`。除外フォルダ・深さ・リンク追従ポリシー（[[hirake-directory-links]]）が自動で揃う
- キャッシュはルート単位（最大 4 ルート）・TTL 10 秒。単一エントリにすると、別フォルダのタブを行き来しただけで毎回作り直しになる
- **リンク先を作った直後は最大 10 秒だけ未解決に見える。** 逆に、消したファイルへのリンクも最大 10 秒は有効なまま描画される
- **索引は描画の前にバックグラウンドで用意する**（`WikiLinkIndex.PrewarmAsync`）。描画は UI スレッドで同期に走るため、そこで初めて作ると走査のぶんだけ画面が止まる。本文に `[[` が無ければ何もしない
- **時間では打ち切らない。** 途中まで作った索引を完全なものとして使うと、同名候補の一部だけが入った状態を「候補 1 件」と誤判定し、曖昧の印も付けずに別のファイルを開いてしまう。しかも結果が実行のたびに変わる
- **やり切れなかった索引は「確定」を名乗らない。** 件数上限（索引は 5,000 件。本文を読まないぶん横断検索の 500 件より多く取る）に達した場合や、走査中に例外が出た場合は `IsComplete = false` になり、候補 1 件でも**曖昧と同じ点線**で示す。「未列挙の範囲に別の同名があるかもしれない」ことを黙って隠さないため。上限到達は `Diagnostics` にも記録する
- 索引の起点は `LinkGraphService.FindWorkspaceRoot` の推定値。フォルダ指定つきのキーは**末尾一致**で登録する（`sub/note` は `a/sub/note.md` にも当たる）。ルートの推定位置に結果が左右されないようにするため

### 同名が複数あるとき

上から順に見て、決まった時点で確定する。

1. `[[sub/note]]` のようにフォルダ指定があれば、それに一致するもの
2. リンク元と同じフォルダにあるもの
3. ルートからの階層が浅いもの
4. それでも複数なら、パス昇順の先頭

4 まで来たものは**確定でない**として扱い、開けるようにしたうえで点線の下線で示す（索引がやり切れていない場合も同じ扱い）。**未解決にはしない。** Wiki 形式では同名が普通に起きるため、そこでリンクを切ると探索できるようにするという目的そのものが達成できない。

## 3 つの表示状態

| 状態 | クラス | 見た目 | 押せるか |
|---|---|---|---|
| 解決 | `.mdv-wikilink` | 通常のリンクと同じ | 開く |
| 確定でない | `+ .mdv-wikilink-ambiguous` | 点線の下線。理由と選ばれたファイルは title に出る | 開く |
| 未解決 | `.mdv-wikilink-broken` | 赤い破線。**`[[...]]` を原文のまま出す** | 押せない（`<a>` ではない） |

未解決を `<a>` にしないのは、「リンクに見えるのに動かない」要素を作らないため。原文のまま出すのは、黙って通常の文字にすると**書いたつもりのリンクが繋がっていないことに気付けない**ため。

## 誤爆させないための受理条件

`[` を見たときに、次をすべて満たす場合だけリンクとして扱う。ひとつでも外れたら既存のパーサへ委ねる（＝対応前と同じ挙動）。

1. 設定 `WikiLinksEnabled` が true
2. `[[` で始まる
3. 直前が `!` でない
4. 同一行内に `]]` がある
5. 内側に `[` `]` を含まない（`[[0][1]]` 対策）
6. 改行を含まない
7. 名前がトリム後 1 文字以上
8. リンクの内側でない（`<a>` を入れ子にしない）
9. 本体が 512 文字以内

コードブロック・インラインコードの中はインラインパーサ自体が呼ばれないため、条件を書くまでもなく安全。

正規化は「前後の空白を落とす・半角の連続空白を 1 個へ畳む・区切りを `/` へ揃える・大文字小文字を無視」。**全角スペースは潰さない**（ファイル名として半角と区別されるため、潰すと実在するファイルを開けなくなる）。

## URL は相対パスで出す

解決したリンクは、文書のフォルダからの**相対パス**（各セグメントを URL エスケープ）＋ `#` フラグメントとして出す。

絶対パス（`C:\...`）で出すと `MarkdownRenderer.RewriteAbsolutePaths` がパス全体をセグメント分割してエスケープするため、**`#` まで 1 セグメントに潰れてフラグメントが壊れる**。相対パスは書き換え対象外なので `#` が残り、`<base>` 経由で [[hirake-uri-scheme]] と同じ仮想ホストへ解決される。

## 副産物: 通常リンクの `#見出し`

`#見出し` を実現するために `DocumentTab` がナビゲーション URL のフラグメントを見るようになった。その結果、**`[表示](other.md#見出し)` という通常の Markdown リンクでも開いた先でスクロールする**ようになった（2026-08-17 まではフラグメントを無視していたため、開くだけで先頭に止まっていた）。

見出しの照合規約は `HirakeUri.FindHeadingLine` と共通（見出しテキストで照合。空白を畳んで大文字小文字を無視）。

ただし**この照合では索引を引かない**（`textOnly` 指定）。見出しの取り出しはリンクのクリック処理から同期で
呼ばれるため、ここでフォルダ走査を始めると画面が止まる。`[[a|表示]]` は表示テキストだけを取り出す。

**見出しテキストと見出し id の両方で照合する。** どちらを優先するかは呼び元で分ける。

| 呼び元 | 優先 | 理由 |
|---|---|---|
| 文書内リンク（`[表示](other.md#target)` / `[[a#見出し]]`） | **id** | URL のフラグメントは本来 id を指す。`{#target}` を持つ見出しと、本文が `target` の見出しが両方あるとき、URL の規約どおり前者へ飛ぶ |
| `hirake://open?heading=` | **見出しテキスト** | [[hirake-uri-scheme]] の既存契約。id は日本語見出しで自動採番になり人間が書けない |

どちらも、優先側で見つからなければもう一方で探す。

**見出しの解決はバックグラウンドで行う。** クリック（ナビゲーションイベント）から同期に呼ぶと、
対象ファイルの読み込みと解析のぶんだけクリックのたびに画面が止まる。`#` が付いていないリンクは
待ちを作らずそのまま開く。

## 設定

`settings.json` の `WikiLinksEnabled`（既定 `true`）。設定 UI は無く、[[hirake-directory-links]] の `FollowDirectoryLinks` と同じ扱い。変更はタブの再読み込みで反映される。
